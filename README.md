# AccessReview · 问题归并与修复验证台

纯浏览器本地运行的无障碍（a11y）扫描问题归并与修复验证工具。React + TypeScript + Vite，无后端，数据存于 `localStorage`。

## 要解决的问题

同一个按钮组件在十几个页面都缺少名称 —— 这是**一个组件根因**，但每一条都是**独立页面上的独立证据**。
AccessReview 把这些命中归并成一个修复组，同时：

- 一次修复候选必须在**每个页面情景中分别复验**；
- **部分通过时未通过 / 待验 / 过期页面不会跟着关闭**，组保持「部分通过」；
- 归并错误可以**拆分 / 合并**，操作前给出影响范围说明；
- 实例**换版**后，旧版本上的通过自动变「过期」，必须重新验证；
- 曾经通过又失败 → 自动标记**修复回归**；
- **重复验证**追加快照、永不覆盖，判定始终取最新一条。

## 领域模型

| 实体 | 说明 |
| --- | --- |
| Page | 被扫描页面 |
| ComponentInstance | 页面上的组件实例（选择器 + 当前代码版本） |
| RuleHit | 规则命中，挂在实例上，带独立证据片段与**采集时版本** |
| FixGroup | 修复组。自动组带归并键 `signature = ruleId @@ componentName`；拆分 / 跨键合并产生的**手工组** `signature = null`，不再自动吸纳新命中 |
| FixCandidate | 一次修复尝试；可多次提交，旧候选复验记录保留溯源 |
| Verification | 页面级复验快照（结论 + 复验时实例版本 + 时间），追加不覆盖 |

### 状态机

- **命中**：未开始 → 待复验 → 通过 / 失败；通过后换版 → 过期；通过后又失败 → 回归。
- **修复组**：未开始 / 待复验 / 全部通过 / **部分通过** / 有失败 / 证据过期 / 修复回归。
  仅当所有页面命中在当前版本均为「通过」才是「全部通过」。

## 关键设计

- **归并稳定性**：归并键是纯函数，与录入顺序、时间戳、ID 无关；自动归并只并入带相同 signature 的自动组，手工组不吸纳命中（测试覆盖顺序无关、增量录入、拆分/合并后行为）。
- **部分通过不连带关闭**：组状态由各页面命中状态聚合，任何 `failed / pending / stale / regressed` 都阻止关闭。
- **版本变化**：证据保留采集版本，复验快照记录复验版本；实例换版后通过项变 stale，组级状态实时重算，换版前用 `explainVersionChange` 报告波及的通过数与组数。
- **撤销重做**：所有变更走纯函数 reducer，历史栈上限 100 步，支持 Ctrl/⌘+Z / Ctrl/⌘+Shift+Z；一次扫描录入（页面+实例+命中）合并为一个历史条目。
- **刷新恢复 / 验证快照 / 一键复位**：`localStorage` 自动持久化；可导出带版本号的 JSON 快照、导入前做结构校验；一键复位本身也可撤销。

## 代码结构

```
src/core/        纯领域层（无 React 依赖，全部可单测）
  types.ts         实体与状态类型
  groups.ts        signature 归并键
  reducer.ts       全部状态变更（录入/候选/复验/拆分/合并/换版/复位）
  selectors.ts     命中与组状态聚合、影响范围解释
  history.ts       撤销重做栈
  seed.ts          示例数据（4 页面 Button + 2 页面 Link）
  *.test.ts        归并稳定性 / 部分通过 / 版本变化 / 重复验证 + 撤销重做
src/state/       store（历史 + 持久化 + 快照）、context
src/ui/          Sidebar / GroupDetail / IngestModal / 通用组件 / 样式
```
