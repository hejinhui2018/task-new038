# AccessReview · 无障碍问题归并与修复验证台

纯浏览器本地运行（React + TypeScript + Vite）的无障碍问题修复工作台。解决设计系统团队的实际痛点：同一个组件根因（例如 icon-only Button 缺少可访问名称）在十几个页面被扫描器重复报告，修一次后有人“一键全关”、有人逐条处理，最后无法确认哪些页面真的验证过。

## 核心模型

- **页面（Page）** 与 **组件实例（ComponentInstance，含代码版本）**
- **规则命中（Finding）**：某页面 × 某实例 × 某规则的一条**独立页面证据**（selector、片段、观察现象、根因键、证据指纹、扫描轮次）
- **修复组（FixGroup）**：可能来自同一组件根因的命中集合
- **修复候选（FixCandidate）**：一次声称的修复（说明 + 包含修复的代码版本）
- **验证快照（Verification）**：在某个页面情景中对当前候选的不可变验证记录
- **影响记录（ImpactEntry）**：每次结构性操作的影响范围解释

## 关键规则

1. **自动归并**：签名 = `规则 ␁ 组件 ␁ 根因键`，三者完全一致才自动归组。
   - 仅进入 `auto` 组；人工拆分/合并产生的组不再自动吸收新命中。
   - 多候选取 id 最小组，决策与录入顺序无关（确定性、稳定）。
   - 刷新证据（即使根因键改变）**不会**把命中自动移组，需人工判断拆分。
2. **逐页独立验证、部分通过不连坐**：每条页面证据的状态只由“当前候选 + 当前证据现场”下它自己的最近验证决定。
   - `open / fixing / partial / resolved`；只有**全部**页面当前有效通过才可关闭组。
3. **证据/版本过期**：验证快照记录候选 id、页面版本、实例版本、扫描轮次、证据指纹；任一现场变化，旧通过结论变为 `stale`，需要重新确认，且只影响该页面这一条证据。
4. **修复回归**：同一证据现场下结论由 pass 翻转为 fail，该页面重新打开，同组其他页面不受影响。
5. **重复验证幂等**：同候选、同现场、同结论的重复提交不产生新快照（但记录“已忽略”）。
6. **拆分/合并**：移走的命中进入新人工组，不携带候选与验证结论；合并归档旧组，影响范围（页面数、证据数）写入影响记录。
7. **候选替换**：旧候选标记 superseded，其下通过只保留为历史快照，全部页面需重新验证。
8. **工程能力**：撤销/重做（Ctrl/⌘+Z / +Shift+Z）、刷新自动恢复（localStorage，含恢复时间提示）、验证快照查看、一键复位。

## 目录结构

```
src/
  core/
    types.ts       领域模型
    hash.ts        稳定证据指纹（FNV-1a）
    grouping.ts    自动归并签名与稳定选组
    commands.ts    纯函数命令（录入/拆分/合并/候选/验证/换版/刷新/复位）
    selectors.ts   派生状态（逐页/逐组状态、快照有效性）
    store.ts       撤销重做 + localStorage 持久化的外部 store
    seed.ts        12 页面 button-name 的演示数据
  ui/              React 组件
  test/            vitest 单测与 RTL 集成测试
```

## 命令

```bash
npm install
npm run dev       # 本地开发
npm test          # 34 个测试（归并稳定性/部分通过/版本变化/重复验证/拆分合并/撤销重做/持久化/UI）
npm run build     # tsc 类型检查 + 生产构建
```

全部数据仅保存在浏览器 localStorage（`access-review:state:v1`），无后端、无网络请求。
